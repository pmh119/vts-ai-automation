🧭 AI 협동 자동화 개발 4단계 플로우

이번 PORT-MIS 선박명 탭 동기화 북마크릿을 만들 때 관제사와 AI가 실제로 주고받은 대화 흐름입니다. 메신저 형태의 대화 흐름을 통해 어떤 식으로 질문과 피드백이 오고 갔는지 확인해 보세요.

1단계. 요구사항 설명 및 1차 코드 생성

내 머릿속에 있는 자동화 아이디어를 AI에게 먼저 가볍게 설명하고, AI의 요청에 따라 브라우저 화면 요소를 마우스 우클릭 후 [검사]하여 찾은 태그 ID 정보를 전달해 1차 코드를 뽑아냅니다.

👤 관제사 (User) "포트미스 관제 입력창에 탭이 여러 개 열릴 때, 탭 이름을 입력된 선박명으로 자동으로 바꿔주는 한 줄짜리 북마크릿을 만들어줘."
🤖 AI 비서 (Assistant) "좋은 아이디어네요! 해당 웹 화면의 구조(HTML)를 알아야 정확히 코드를 짤 수 있습니다. 브라우저 화면에서 **탭 부분**과 **선박명이 입력되는 칸**에 각각 마우스 우클릭 후 **[검사]**를 누르고, 개발자 창에 하이라이트 표시되는 HTML 코드의 id나 class 값을 알려주실 수 있나요?"
👤 관제사 (User) "브라우저 우클릭 검사로 HTML을 확인해 보니까 탭 영역의 ID는 mf_tacMain_tabhost이고, 각 선박명 입력창의 ID 패턴은 vsslKorNmD로 지정되어 있어."
🤖 AI 비서 (Assistant) "감사합니다! 제공해 주신 탭 영역 ID(mf_tacMain_tabhost)와 입력 필드 ID 규칙(vsslKorNmD)을 기반으로, 탭 컨테이너와 선박명을 매칭하여 탭 이름을 바꿔주는 1차 북마크릿 코드를 작성해 드릴게요."

2단계. 실제 현장 대조 및 문제 발견 (버그 확인)

AI가 준 코드를 현장 PC에서 구동해 봅니다. 이 단계에서 미처 생각지 못했던 실무 에러나 데이터가 꼬이는 버그를 발견합니다.

👤 관제사 (User) "탭이 4개 열려있는데 3개는 선명과 정확히 일치하는데 한 개 탭만 다른 선박명으로 잘못 표시돼. 무슨 테스트를 해봐야 원인을 알 수 있을까?"
🤖 AI 비서 (Assistant) "탭이 꼬이는 오류의 원인을 진단해야 합니다. 특정 PC의 브라우저 DOM(구조) 상태를 들여다볼 수 있도록 F12 개발자 도구의 콘솔 탭에 붙여넣어 볼 [진단 코드]를 작성해 드릴게요."

3단계. 브라우저 개발자 도구(F12) 콘솔을 활용한 정밀 진단

AI가 제공한 진단 코드를 브라우저에 주입하여 원인이 되는 숨어있는 웹 요소의 개수와 매칭 로그 데이터를 확보합니다.

👤 관제사 (User) "(AI가 알려준 진단 스크립트를 F12 Console에 붙여넣고 즉시 실행)"
🤖 AI 비서 (Assistant) "감지된 탭 개수와 백그라운드에 남아있는 좀비 컨텐츠 개수가 일치하는지 알려주시면, 유령 탭을 걸러내고 무조건 '눈에 보이는 활성화된 값' 위주로 저격하도록 소스를 보정해 드리겠습니다."

4단계. 진단 결과 제보 및 최종 마감

진단 결과를 바탕으로 AI는 정확한 오류 원인을 찾아내고, 중복 맵핑이 원천적으로 차단된 무결점 최종 코드를 제공합니다.

👤 관제사 (User) "진단 결과 로그를 보니까 '눈에 보이는 실제 탭 개수: 1개 / 메모리에 남아있는 컨텐츠 창 개수: 6개'라고 나와. 유령 좀비 탭이 5개나 있고, 고유키를 포함하는 창이 3개나 중복 존재한다고 경고(🚨 위험)가 뜨네."
🤖 AI 비서 (Assistant) "명확한 원인을 찾았습니다! 닫힌 탭의 잔재(좀비 div)와 하위 탭 구조의 ID 패턴이 겹쳐 includes() 방식에서 오작동한 것입니다. 순정 ID 규칙인 'mf_tacMain_contents_' + k와 1:1로 완전 일치(===)하는 부모 창만 getElementById로 다이렉트 저격하여 해결해 드리겠습니다."
🔍 실전 케이스 스터디: PORT-MIS 탭 불일치 진단 사례

"어떤 PC에서는 탭이 꼬이고 작동을 안 해요!"에 대처했던 정밀 분석기법

당시 AI가 관제사에게 건네주어 원인을 밝혀냈던 F12 콘솔용 진단 스크립트입니다. 브라우저가 화면을 그릴 때 내부적으로 탭과 창을 어떻게 맵핑하고 있는지 정확히 스캔해 줍니다.

(function(){ console.clear(); console.log("🚀 [평택VTS 특정 PC 오작동 환경 분석 시작]"); var host = document.getElementById('mf_tacMain_tabhost') || document.querySelector('.w2tabcontrol_tabs'); if(!host) { console.error("❌ 오류: 탭 호스트(mf_tacMain_tabhost)를 찾을 수 없습니다."); return; } var anchors = host.querySelectorAll('a[id*="tabHTML"]') || host.querySelectorAll('a'); var contents = document.querySelectorAll('.w2tabcontrol_contents'); console.log(`📌 현재 눈에 보이는 실제 탭 개수: ${anchors.length}개`); console.log(`📌 메모리(DOM)에 남아있는 컨텐츠 창 개수: ${contents.length}개`); if(contents.length > anchors.length) { console.warn(`⚠️ 경고: 실제 탭보다 컨텐츠 창이 ${contents.length - anchors.length}개 더 많습니다. (유령 좀비 탭 발생 PC 확인)`); } // ... 이하 탭별 1:1 세부 매칭 분석 ... })();
💻 특정 오작동 PC에서 튀어나온 실제 진단 결과 로그:
🚀 [평택VTS 특정 PC 오작동 환경 분석 시작]
📌 현재 눈에 보이는 실제 탭 개수: 1개
📌 메모리(DOM)에 남아있는 컨텐츠 창 개수: 6개
⚠️ 경고: 실제 탭보다 컨텐츠 창이 5개 더 많습니다. (유령 좀비 탭 발생)
🚨 위험: 고유키 [M4049_290]를 포함하는 좀비 창이 3개 중복 존재합니다!
💡 진단으로 알게 된 2가지 오작동 원인과 극복과정
  • 1. 유령 좀비 탭의 방해: 웹스퀘어 엔진은 사용자가 탭을 닫아도 화면에서만 가리고 메모리상에는 div 영역을 그대로 남겨둡니다. 기존 코드는 탭을 순회하다가 과거에 이미 닫아버린 유령 창을 먼저 가져와 탭 이름을 덮어쓰는 실수를 저질렀습니다.
  • 2. 하위 탭 컨트롤러의 간섭 (이름 불일치 유발): 관제창 안에 또 다른 하위 서브 메뉴 탭 시스템이 중첩되어 설계된 경우, 탭 ID를 includes()로 검사하면 하위 영역까지 싹 다 매칭(1개 탭에 3개 중복 잡힘)되는 버그가 확인되었습니다.
⚙️ 최적의 해결책 도출:
유령 탭을 무시하기 위해 도입했던 offsetParent !== null(눈에 보이는 것만 타격) 필터는 사용자가 탭을 오고 갈 때 비활성화된 진짜 탭의 연동을 풀어버리는 부작용이 있었습니다.
결국, "진짜 탭에 맵핑된 최상위 고유 ID 규칙('mf_tacMain_contents_' + k)"과 100% 글자 하나 안 틀리고 동일(===)한 단 하나의 부모 컨테이너만 직접 저격(getElementById)하게 함으로써, 전국 어느 VTS PC에서도 오류가 생길 수 없는 '무결점 감시 엔진'을 확보했습니다.
💬 AI에게 설명하고 피드백을 주는 올바른 대화 흐름 비교

AI는 훌륭한 파트너이지만, 현재 내 화면의 버그 원인을 직접 들여다볼 수 없습니다. 아래의 두 대화 흐름을 비교하여, 어떻게 피드백을 주어야 버그를 순식간에 해결할 수 있는지 직관적으로 파악해 보세요.

❌ 아쉬운 대화 흐름 (진단 생략)
👤 관제사 (User) "코드를 등록해봤는데 여전히 똑같이 선박명이 꼬이네요. 코드 다시 만들어 주세요."
🤖 AI 비서 (Assistant) "(어디가 어떻게 꼬이는지 알 수 없어 막연히 탭 감시 트리거 부분만 바꿔서 추측성 코드 재전송)"

⚠️ 결과: 버그의 원인(좀비 탭, 하위 중복 ID)을 전혀 찾지 못해, 코드를 여러 번 다시 짜도 계속 동일한 오류가 재발합니다.

✅ 추천하는 대화 흐름 (로그 제공)
👤 관제사 (User) "진단 결과 실제 탭은 1개인데 메모리에 남은 창은 6개이고, 특정 키를 포함하는 좀비 창이 3개나 겹쳐있어 🚨 경고가 발생하는 게 오작동 원인인 듯해."

✨ 결과: 문제의 원인이 단번에 표적 저격되어, 10분 이내에 완벽히 개선된 안정적인 코드가 보장됩니다.
